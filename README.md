# RepJob

Ищет в справочниках компании с проседающим рейтингом — кандидатов на работу
с репутацией. Отбирает по диапазону оценки, считает, сколько пятёрок нужно
до цели, расставляет приоритет и выгружает готовый список для обзвона.

Два интерфейса к одному движку:

- **`leadfinder`** — консольная утилита, удобна для больших прогонов;
- **`bot`** — Telegram-бот, чтобы дёргать выдачу с телефона.

# Telegram-бот

```bash
export BOT_TOKEN=токен_от_BotFather
export DGIS_API_KEY=ключ_2gis
export BOT_ALLOWED_IDS=твой_telegram_id

python -m bot
```

## Команды

| Команда | Что делает |
|---|---|
| `/find` | Мастер: город → ниша кнопками → выдача и CSV файлом |
| `/find Казань медицина` | То же самое одной строкой |
| `/calc 3.4 48` | Сколько пятёрок нужно до 4.5 и за сколько месяцев |
| `/calc 3.4 48 4.3` | То же со своей целью |
| `/csv` | Прислать последнюю выдачу файлом ещё раз |
| `/id` | Узнать свой Telegram ID |

`/calc` полезнее всего на встрече: считает при клиенте за пару секунд.

## Доступ

Бот закрытый. Пускает только тех, чьи ID перечислены в `BOT_ALLOWED_IDS`
через запятую. Пока переменная пуста, бот не пустит никого и в ответ покажет
собеседнику его ID — чтобы можно было вписать себя и перезапуститься.
Команда `/id` работает всегда, в том числе для незнакомых.

Это не формальность: ключ 2GIS квотируется, и открытый бот выест лимит за
вечер.

## Деплой на сервер

Git на свежем VPS может быть не установлен, а ставит его как раз скрипт —
поэтому сам скрипт забираем через curl, а не клонированием.

```bash
curl -fsSL https://raw.githubusercontent.com/TAAAAAAAAAAAAAAAAmik/RepJob/claude/empty-repository-eskyes/deploy/install.sh -o install.sh
sudo bash install.sh
```

Скрипт остановится и попросит вписать ключи:

```bash
nano /opt/repjob/.env          # BOT_TOKEN и DGIS_API_KEY
sudo bash /opt/repjob/deploy/install.sh
```

Второй запуск поднимет сервис и проверит, что тот действительно работает —
если нет, покажет журнал. Дальше бот скажет, что пока никого не пускает:
напиши ему `/id`, впиши номер в `BOT_ALLOWED_IDS` и перезапусти.

Скрипт идемпотентный: этой же командой потом обновляется код. Что он
делает — ставит python и git, заводит системного пользователя `repjob`
без shell и домашнего каталога, клонирует репозиторий в `/opt/repjob`,
собирает venv, кладёт systemd-юнит и включает автозапуск.

Ключи лежат в `/opt/repjob/.env` с правами 600 у пользователя сервиса —
в репозиторий они не попадают, `.env` в `.gitignore`.

Нужен Debian или Ubuntu. На другой системе скрипт честно скажет об этом
и не станет ничего ломать.

## Если root не дали

Некоторые хостеры не выдают sudo. Проверить:

```bash
sudo -l
```

Ответ «user ... may not run sudo» означает, что системная установка выше
не сработает. Есть вариант без root — всё живёт в `~/repjob`:

```bash
curl -fsSL https://raw.githubusercontent.com/TAAAAAAAAAAAAAAAAmik/RepJob/claude/empty-repository-eskyes/deploy/install-user.sh -o install-user.sh
bash install-user.sh
```

Дальше как обычно: вписать ключи в `~/repjob/.env` и запустить скрипт ещё
раз. Управление:

```bash
~/repjob/deploy/restart.sh     # перезапуск
~/repjob/deploy/stop.sh        # остановить
tail -f ~/repjob/bot.log       # журнал
```

Чем отличается от системной установки:

- код скачивается тарболлом, а не клонируется — git на урезанном образе
  может отсутствовать, а поставить его без root нельзя;
- зависимости идут в venv, а если модуля `venv` нет — в домашний каталог;
- автозапуск через cron: `@reboot` поднимает бота после перезагрузки,
  проверка раз в пять минут возвращает его после падения. Повторный
  запуск отсекается флоком, так что двух ботов не будет;
- лог подрезается самим скриптом, раз logrotate без root не настроить.

Процессом управляем через PID-файл и файл блокировки, а не через `pkill`
по шаблону: шаблон вроде `-m bot` совпадает с любым процессом, где эта
строка просто есть в командной строке. При чтении PID сверяется командная
строка процесса, так что устаревший PID-файл не приведёт к остановке
чужого процесса.

## Безопасность сервера

Бот работает от непривилегированного пользователя, юнит закрывает ему всё
лишнее (`ProtectSystem=strict`, `ProtectHome`, `NoNewPrivileges`). Но сам
сервер стоит закрыть отдельно, до всякого бота:

```bash
# ключи вместо пароля
ssh-copy-id tamik@сервер
# в /etc/ssh/sshd_config:
#   PasswordAuthentication no
#   PermitRootLogin no
systemctl restart ssh

apt install fail2ban
```

Пароль, который хоть раз попал в переписку, мессенджер или историю команд,
считается скомпрометированным — меняй, не откладывая.

# leadfinder (консоль)

## Быстрый старт

```bash
pip install -r requirements.txt

# посмотреть, как выглядит результат — без ключей и сети
python -m leadfinder --demo

# реальный сбор
export DGIS_API_KEY=твой_ключ
python -m leadfinder --city Казань --niche медицина авто --out leads.csv
```

## Откуда берутся данные

**2GIS Places API — основной источник.** Официальный, ключ бесплатный на
[platform.2gis.ru](https://platform.2gis.ru). Единственный из двух, который отдаёт
рейтинг и число отзывов прямо в ответе — на нём и держится весь отбор.

**Яндекс — дополнение, не замена.** Важное ограничение, из-за которого
устроено именно так: официальный Яндекс «Поиск по организациям» отдаёт
название, адрес, телефон и категорию, но **рейтинга и числа отзывов в этом
API нет** — они живут только в интерфейсе Яндекс.Карт. Поэтому:

1. фильтруем по рейтингу через 2GIS, где цифры доступны легально;
2. для каждого отобранного лида кладём в выгрузку ссылку на его карточку
   в Яндексе;
3. рейтинг на Яндексе смотрим глазами по 20–30 отобранным компаниям перед
   звонком — это всё равно делается руками при подготовке к разговору.

Обходить это парсингом выдачи Яндекс.Карт не нужно: это против их правил
использования, а на финальном списке в пару десятков компаний ручная
проверка занимает десять минут и заодно даёт прочитать отзывы — без чего
на звонок всё равно не выйдешь.

С ключом Яндекса (`--yandex`, ключ в `YANDEX_API_KEY`) в выгрузке будут
прямые ссылки на карточки; без ключа — ссылки на поиск, открываются в один
клик.

## Кого отбираем

Границы по умолчанию — профиль клиента, которому услуга нужна и которого
реально вытянуть:

| Параметр | По умолчанию | Почему так |
|---|---|---|
| Рейтинг | 3.0 – 4.2 | Ниже 3.0 — обычно реально плохой сервис. Выше 4.2 — не болит |
| Отзывов | от 10 | Меньше — рейтинг статистический шум, качнётся сам |
| Телефон | не обязателен | `--require-phone`, если нужен только готовый к обзвону список |

## Приоритет лида

Скоринг 0–100 из двух половин:

- **насколько больно** — разрыв до 4.5, насыщается на 1.5 звезды;
- **есть ли кого просить об отзыве** — число отзывов как прокси трафика,
  по логарифму, насыщается на 300.

Отсутствие телефона снижает итог на 20% — но только если телефоны в выборке
есть хоть у кого-то. Дальше: 70+ — горячий, 45–70 —
рабочий, ниже — холодный.

Практический смысл: точка с 3.6 и 156 отзывами обгоняет точку с 3.8 и 214 —
трафик почти тот же, а просадка больше, значит владельцу больнее. И обе
обгоняют 4.15 с 11 отзывами, где и не болит, и собирать не с кого.

## Параметры

```
--city Казань              город (обязателен, кроме --demo)
--niche медицина авто      пресеты ниш или произвольные запросы
--rating-min 3.0           нижняя граница рейтинга
--rating-max 4.2           верхняя граница
--min-reviews 10           минимум отзывов
--require-phone            только с телефоном
--limit 50                 оставить N лучших
--out leads.csv            куда сохранить
--json leads.json          дополнительно JSON
--yandex                   искать точные карточки Яндекса (нужен ключ)
--demo                     прогон на встроенном примере
-v                         подробный лог
```

Пресеты ниш: `медицина`, `красота`, `авто`, `спорт`, `дети`, `еда`, `быт`.
Всё, что не совпало с пресетом, уходит в поиск как есть — можно писать
`--niche "ремонт обуви"`.

## Выгрузка

CSV с точкой с запятой и BOM — открывается в русском Excel двойным кликом,
без мастера импорта и без кракозябр. Колонки идут в порядке работы:
приоритет, оценка лида, название, рейтинг, отзывы, сколько пятёрок нужно,
телефон, адрес, ссылки на обе карточки.

## Особенности 2GIS, проверенные на живых данных

Всё ниже выяснено прогоном по реальному городу, а не взято из документации.

**`page_size` максимум 10.** Больше — ошибка 400. Это определяет стоимость
прогона: одна страница = один запрос из лимита ключа.

**Демо-ключ не отдаёт контакты.** Поле `items.contact_groups` запрашивается,
но в ответе его просто нет — контакты платные. Поэтому колонка «Телефон»
пустая, а номер берётся в один клик по ссылке на карточку. Скоринг это
учитывает: когда телефонов нет ни у кого, штраф за их отсутствие не
начисляется, иначе он одинаково просаживает всех и красит горячие лиды
в холодные.

**Рейтингов два, и они расходятся.** В ответе приходят обе пары:

| Поле | Что это |
|---|---|
| `general_rating` / `general_review_count` | Карточка конкретного филиала, только отзывы 2GIS |
| `org_rating` / `org_review_count` | Организация целиком, вместе с Flamp |

Расхождение бывает заметным — встречалось 4.9 против 4.3 у одной клиники,
причём в обе стороны. Фильтруем по филиальному (это то, что видит человек
на карточке точки), но в выгрузку кладём оба: на встрече пригодятся оба
числа.

## Сколько запросов стоит прогон

У демо-ключа 1000 запросов на месяц, так что считать приходится:

| Что | Запросов |
|---|---|
| Одна страница выдачи (до 10 организаций) | 1 |
| Определение региона по городу | 1, дальше из кэша |
| Поиск по пресету в боте (5 рубрик × 6 страниц) | ~30 |
| Поиск из консоли с `--max-pages 10` | ~50 |

То есть демо-ключа хватает примерно на 30 полных поисков. Для старта это
с запасом: 150–200 лидов набираются за 5–7 прогонов. Счётчик потраченных
запросов печатается после каждого запуска консольной версии.

## Если 2GIS отвечает ошибкой

Сервис отдаёт HTTP 200 даже на ошибку, настоящий код лежит в `meta.code` —
клиент это учитывает. Частые случаи:

- `403 Authorization error` — ключ не тот или не активирован;
- пустой результат по всем запросам — проверь город: `--city` должен
  совпадать с названием региона в 2GIS (при несовпадении клиент покажет
  список доступных).
